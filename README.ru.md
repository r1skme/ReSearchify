# ReSearchify

**Находи нужный код за пару команд — даже в больших проектах.**

ReSearchify индексирует исходники, а затем ищет функции, переменные, точные фрагменты и регулярные выражения без повторного перебора каждого файла при каждом запросе. Написан на C++20. Основная команда — **`rs`**.

## Скачать и запустить

Выбери архив под свою систему из последнего [preview-релиза на GitHub](https://github.com/r1skme/ReSearchify/releases):

| Система | Архив | Программа |
| --- | --- | --- |
| Windows x64 | `ReSearchify-Windows-x64.zip` | `rs.exe` |
| macOS Apple Silicon (M1–M4+) | `ReSearchify-macOS-arm64.tar.gz` | `rs` |
| macOS Intel | `ReSearchify-macOS-x64.tar.gz` | `rs` |
| Linux x86-64 | `ReSearchify-Linux-x64.tar.gz` | `rs` |
| Linux ARM64 | `ReSearchify-Linux-arm64.tar.gz` | `rs` |

Скачай `SHA256SUMS.txt` из **того же релиза** и сверь SHA-256 архива до распаковки. Внутри — готовая консольная программа и README на двух языках. Python, Node.js и компилятор не нужны.

**Windows (PowerShell):** распакуй ZIP в `C:\Tools\ReSearchify`, затем в папке своего проекта выполни:

```powershell
$env:Path += ';C:\Tools\ReSearchify'
rs -i .                             # Создать индекс проекта
rs -s "RenderFrame"                # Найти идентификатор
rs -rs "Render[A-Za-z]*Frame"      # Регулярное выражение
rs -u                               # Обновить индекс
```

**macOS / Linux (Терминал):** распакуй подходящий `.tar.gz`, проверь запуск командой `./rs --version`, затем добавь папку с `rs` в `PATH` или вызывай программу по полному пути. В выбранном проекте:

```sh
rs -i .
rs -s RenderFrame
rs -u
```

Linux-архивы собираются на Ubuntu 22.04: для старых дистрибутивов может потребоваться сборка из исходников. Сборки macOS рассчитаны на macOS 13.3+ и **не проходят нотариализацию Apple** (Gatekeeper может показать предупреждение). Новый релиз появляется только после успешной сборки и тестов всех пяти платформ и проверки санитайзерами в Linux.

Подробная установка и проверка хешей — в [INSTALL.md](docs/INSTALL.md). Кнопка **Code → Download ZIP** скачивает исходники, а не готовую программу.

## Команды

Когда `rs.exe` добавлен в `PATH`, команды работают из любой подпапки проиндексированного проекта:

| Команда | Что делает | Пример применения |
| --- | --- | --- |
| `rs -i .` | Создаёт индекс текущей папки | Первый запуск в проекте |
| `rs -s RenderFrame` | Ищет идентификатор `RenderFrame` | Функция, класс, переменная |
| `rs -s "RenderFrame AND NOT deprecated"` | Ищет файлы с `RenderFrame`, но без `deprecated` | Убрать старые реализации |
| `rs -rs "worker_[0-9]+"` | Ищет по регулярному выражению | Похожие имена с цифрами |
| `rs -l "std::vector<int>"` | Ищет точный фрагмент текста | Типы, вызовы, символы |
| `rs -f "*.cpp"` | Выводит подходящие имена файлов | Найти все `.cpp` |
| `rs -r src/main.cpp --lines 20:45` | Показывает строки 20–45 из индекса | Быстро посмотреть нужный участок |
| `rs -u` | Проверяет изменения и обновляет индекс | После редактирования кода |
| `rs -st` | Показывает число файлов, строк и размер индекса | Посмотреть статистику |
| `rs verify` | Проверяет целостность индекса | Если подозреваешь повреждение |
| `rs --help` | Выводит все команды и параметры | Узнать дополнительные возможности |

Короткие и полные команды равнозначны: можно писать `rs init`, `rs find`, `rs read`, `rs update` и `rs status`.

**Как устроен поиск:** регистр букв имеет значение. `AND`, `OR`, `NOT` и скобки объединяют условия **по файлам**. Для точного текста с пробелами и знаками используй `-l`; для шаблонов — `-rs`. Индекс хранится в `.researchify/` внутри проекта. Команда `rs -u` по умолчанию проверяет содержимое файлов; `--trust-mtime` ускоряет проверку, но менее надёжен.

### Примеры

**Найти рабочую реализацию, исключив устаревшую:**

```powershell
rs -s "(RenderFrame OR DrawFrame) AND NOT deprecated" --path "src/**"
```

`OR` ищет любой из двух вариантов имени, `AND NOT` исключает файлы с `deprecated`, а `--path` ограничивает поиск папкой `src/`.

**Найти фрагмент с символами `<` и `>`:**

```powershell
rs -l "#include <vector>" --limit 10
```

`-l` ищет именно этот текст, а не отдельные слова. `--limit 10` ограничивает выдачу десятью файлами; само вычисление совпадений может потребовать больше работы.

**Найти группу похожих функций:**

```powershell
rs -rs "worker_[0-9]+" --path "src/**" --json
```

`[0-9]+` означает одну или несколько цифр. `--json` возвращает структурированные данные — их удобно читать скриптам и ИИ-агентам.

Полный синтаксис: [QUERY.md](docs/QUERY.md).

## Почему ReSearchify, а не обычный поиск?

| | `grep` / `ripgrep` | Everything | ReSearchify |
| --- | --- | --- | --- |
| Принцип работы | Обычно читает файлы заново при каждом запуске | Очень быстрый индекс имён файлов и путей | Сохраняет **индекс содержимого исходников** |
| Много запросов подряд | Повторная обработка файлов | Быстрый поиск по именам | Использует уже построенный индекс |
| `AND`, `OR`, `NOT` по файлам | Часто нужны дополнительные команды и пайпы | Другой язык запросов | Поддерживается сразу |
| Точный текст и regex | Сильная сторона, особенно у `ripgrep` | Поиск содержимого устроен отдельно от индекса имён | Оба режима через один CLI |
| Работа с ИИ-агентом | Терминал и скрипты | В основном Windows-команды | JSON, JSONL, MCP, чтение строк |
| Подготовка и память на диске | Индекс не нужен | Нужен Everything | Нужно один раз создать индекс |

Для разового поиска в небольшом проекте **`ripgrep` — отличный выбор**. ReSearchify удобнее, когда ты часто ищешь в большом проекте, комбинируешь условия или запускаешь десятки запросов из агента. Everything отлично ищет файлы по имени; ReSearchify рассчитан прежде всего на **содержимое кода**. Это разные задачи — мы не утверждаем, что ReSearchify всегда быстрее всех.

### Результаты тестирования

Результаты текущей ветки оптимизации и команды для повторения приведены в [отчёте о производительности](docs/PERFORMANCE_OPTIMIZATION.md). Там отдельно учитываются построение индекса, поиск, сравнение с ripgrep и реально проверенные платформы. Исторические цифры v1/v2 ниже **не являются измерениями этой ветки**.

Измерения на одном синтетическом корпусе: **100 000 файлов, 5 000 000 строк, около 350 МиБ исходного текста**. Сравниваются предыдущий движок CodeSearch v1 и движок v2, на основе которого сделан ReSearchify:

| Показатель | v1 | v2 / основа ReSearchify |
| --- | ---: | ---: |
| Размер первоначального индекса | 682 МиБ | **483 МиБ** |
| Открытие индекса | 300 мс | **7,14 мс** |
| Редкий идентификатор, повторный запрос в открытом процессе | 1,50 мс | **0,080 мс** |
| Слово, встречающееся во всех 100 000 файлов | 4,87 с | **0,476 с** |
| Рост индекса при изменении одного файла | около 11,7 МБ | **около 16 КБ** |

Индекс стал **на 29% меньше** на этом наборе данных; поиск редкого терма внутри открытого процесса ускорился примерно **в 19 раз**. Это **сравнение версий проекта, а не бенчмарк против `ripgrep`, `grep` или Everything**. Результаты получены не на Windows и зависят от оборудования, кэша и самого запроса. Широкий regex по-прежнему может быть медленным (около 19,9 с в проверенном v2), а строгая проверка обновления читает неизменённые файлы для обнаружения скрытых изменений. Методика и ограничения: [BENCHMARKS.md](docs/BENCHMARKS.md).

### Управление производительностью в текущих исходниках

```sh
rs -l "needle_42 = 0;" --threads 0 --profile --json
rs -l "needle_42 = 0;" --threads 1 --json
rs -u --profile-stages --json
```

По умолчанию число поисковых потоков выбирается адаптивно (`--threads 0`); `--threads 1` принудительно включает последовательную проверку. Несколько потоков используются только для достаточно большой проверки содержимого. Маленькие и селективные запросы, поиск только по posting lists и regex сейчас остаются последовательными. Лимиты кандидатов и прочитанных байтов общие на запрос, а counts, ранжирование и пагинация сохраняются.

`--profile` добавляет стадии и счётчики поиска в `metrics.profile`, а `--profile-stages` при индексации/обновлении — в `stage_profile`. Это диагностика по запросу: суммы времени нескольких потоков нельзя прибавлять к общему времени выполнения. Без этих флагов лишние поля профилирования не появляются.

Новый профиль `compact` добавляет небольшой необязательный фильтр документов для literal-поиска без полного триграммного индекса. `fast` сохраняет триграммные posting lists. Старые индексы формата 2 продолжают читаться; полная компактизация может дополнить их фильтрами. Отсутствующий фильтр означает обычную точную проверку, а не пропуск документа. CRC и fingerprint не отключаются; обязательных SIMD-инструкций и новых runtime-зависимостей нет.

Эти возможности относятся к текущим исходникам: ранее скачанный релиз может их ещё не содержать. Параметры установленной версии показывает `rs schema find --json`.

## Для ИИ-агентов

Скинь агенту ссылку на репозиторий и следующее задание:

> Настрой ReSearchify для моего проекта. Прочитай `AGENTS.md` и `skills/researchify/SKILL.md`. Скачай последний проверенный архив из Releases для моей ОС и архитектуры, сверь SHA-256 с `SHA256SUMS.txt` и установи `rs` (или `rs.exe` на Windows). Папку для индексации согласуй со мной. Покажи один поиск и объясни обновление индекса. Для следующих запросов используй JSON. Если подходящего релиза нет, спроси перед сборкой из исходников.

Агенту нужны права на запуск программ на твоём компьютере. Обычный чат без доступа к компьютеру не сможет установить утилиту за тебя.

Если GitHub CLI уже авторизован, можно установить через PowerShell:

```powershell
.\scripts\install.ps1              # Скачивает проверенный релиз в папку пользователя
rs -s RenderFrame --json --limit 8
```

Для интеграции:

```powershell
rs capabilities --json              # Какие возможности и ограничения есть
rs schema find --json              # Параметры поиска в машинном формате
rs serve --stdio --root .          # Много запросов в одном процессе (JSONL)
rs mcp --stdio --root .            # MCP-инструменты для совместимых агентов
```

Для агента с терминалом отдельный плагин не требуется. Для MCP потребуется поддерживаемый клиент; подробности в [AGENT_API.md](docs/AGENT_API.md) и [примере конфигурации](examples/mcp-client.json).

## Сборка из исходников

Нужен CMake 3.21+ и Visual Studio 2022 с компонентами разработки C++ (Windows), либо компилятор C++20 и CMake 3.20+ (Linux/macOS).

**Windows — PowerShell:**

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DBUILD_TESTING=ON
cmake --build build --config Release --parallel 8
ctest --test-dir build -C Release --output-on-failure
.\build\Release\rs.exe --help
```

**Linux / macOS:**

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build build --parallel 8
ctest --test-dir build --output-on-failure
./build/rs --help
```

В ядре **нет сторонних библиотек**. Windows-сборка по умолчанию использует статический runtime MSVC. CI проверяет Windows x64, Linux x64/ARM64, macOS Intel/Apple Silicon, дополнительную Linux-сборку Clang и Linux с санитайзерами: [workflow](.github/workflows/windows.yml). Само наличие CI ещё не подтверждает успешное выполнение — перед использованием сборки нужно проверить результат запуска.
